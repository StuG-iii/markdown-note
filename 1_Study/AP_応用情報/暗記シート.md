## 優先度S

### セキュリティ

| 用語                 | 一言定義                                               | 注釈・備考                                                          |
| -------------------- | ------------------------------------------------------ | ------------------------------------------------------------------- |
| 共通鍵暗号方式       | 暗号化と復号に同じ鍵を使う方式                         | 高速だが、鍵配送の安全確保が課題                                    |
| 公開鍵暗号方式       | 公開鍵と秘密鍵の組で使う方式                           | 鍵配送問題に強いが、共通鍵暗号より一般に低速                        |
| 電子署名             | 送信者本人性と改ざん検知を確認する仕組み               | 「秘密鍵で署名し、公開鍵で検証」が基本                              |
| デジタル証明書       | 公開鍵が本人のものであることを証明する電子証明書       | 公開鍵そのものではなく、公開鍵の正当性を証明するもの                |
| PKI                  | 公開鍵暗号方式の証明書を発行・管理する仕組み           | 認証局（CA）を中心とした仕組みとして出やすい                        |
| ハッシュ関数         | 任意長データから固定長の要約値を求める関数             | 暗号化ではない。「改ざん検知」に使う                                |
| 認証                 | 利用者が誰かを確認すること                             | 「本人確認」。認可と役割が違う                                      |
| 認可                 | 何をしてよいかを許可すること                           | 認証後に行う処理として出ることが多い                                |
| 多要素認証           | 異なる種類の要素を組み合わせる認証                     | 知識・所持・生体の異種組合せが重要。同じ種類2つでは多要素にならない |
| ワンタイムパスワード | 一度だけ使える使い捨てパスワード                       | 漏れても再利用されにくい点が利点                                    |
| SQLインジェクション  | 入力欄などからSQL文を不正操作する攻撃                  | DBを直接狙う攻撃。対策はプレースホルダ利用が定番                    |
| XSS                  | Webページに悪意あるスクリプトを埋め込む攻撃            | 利用者のブラウザ上で動くのがポイント                                |
| CSRF                 | 利用者に意図しないリクエストを送らせる攻撃             | 「利用者がログイン済み」であることを悪用する                        |
| DoS攻撃              | 単一または少数から大量負荷を与えて妨害する攻撃         | サービス妨害が目的。情報窃取が主目的ではない                        |
| DDoS攻撃             | 多数の端末から集中攻撃する妨害攻撃                     | ボット化された多数端末から行われる点がDoSと違う                     |
| 標的型攻撃           | 特定組織や個人を狙って行う攻撃                         | 添付ファイルやメール文面が巧妙なのが特徴                            |
| ゼロデイ攻撃         | 修正前の脆弱性を突く攻撃                               | 「発見直後で未対策」の弱点を突くのが要点                            |
| 脆弱性               | セキュリティ上の弱点                                   | 単なるバグ全般ではなく、攻撃に利用可能な弱点                        |
| パッチ管理           | 修正プログラムの適用状況を管理すること                 | 配布だけでなく、適用漏れ防止まで含めて考える                        |
| ファイアウォール     | 通信ルールに基づいて通過や遮断を行う仕組み             | 主にネットワークやポート単位で制御するイメージ                      |
| WAF                  | Webアプリへの攻撃を検知・防御する仕組み                | SQLインジェクションやXSS対策として出やすい                          |
| IDS                  | 不正侵入や異常を検知する仕組み                         | 検知が中心。遮断まで行うとは限らない                                |
| IPS                  | 不正侵入や異常を検知し遮断も行う仕組み                 | IDSより一歩踏み込み、自動防御まで行う                               |
| DMZ                  | 外部公開サーバを内部ネットワークと分離して置く中間領域 | Webサーバやメールサーバを置く典型構成が頻出                         |
| VPN                  | 公衆回線上に仮想的な専用線環境を作る仕組み             | インターネット経由でも安全に拠点間接続できる                        |
| サンドボックス       | 制限された隔離環境でプログラムを動かす仕組み           | 怪しいプログラムの被害拡大防止に使う                                |
| リスク回避           | リスクの原因そのものをなくす対応                       | 例：危険な機能自体をやめる                                          |
| リスク低減           | 発生確率や影響を小さくする対応                         | 最も一般的な対策。防御策導入がこれに当たりやすい                    |
| リスク移転           | 保険や委託で第三者へ負担を移す対応                     | リスク自体が消えるわけではない点に注意                              |
| リスク保有           | 対策コストなどを考慮して受け入れる対応                 | 「何もしない」とは限らず、判断して受容すること                      |

## 優先度A

### ネットワーク

| 用語                   | 一言定義                                                      | 注釈・備考                                                           |
| ---------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------- |
| LAN                    | 限定された範囲内のネットワーク                                | 社内や家庭内などの近距離ネットワーク                                 |
| WAN                    | 広域にまたがるネットワーク                                    | 拠点間接続やインターネット側の広い範囲を含む                         |
| TCP                    | 信頼性重視で順序保証や再送制御を行う通信方式                  | 正確に届けることを重視。UDPより制御が多い                            |
| UDP                    | 高速で軽量だが到達保証を行わない通信方式                      | 音声・動画・DNSなど、速度重視用途で使われやすい                      |
| IPアドレス             | ネットワーク上の論理的な住所                                  | 経路制御で使う住所。機器そのものの固定番号とは限らない               |
| MACアドレス            | NICに割り当てられた物理的な住所                               | 同一LAN内での識別に使う。IPアドレスと役割が違う                      |
| サブネットマスク       | IPアドレスのうちネットワーク部を示す値                        | どこまでがネットワーク部かを判断するための値                         |
| DNS                    | ドメイン名とIPアドレスを対応付ける仕組み                      | 名前解決を行う。IP自動配布ではない                                   |
| DHCP                   | IPアドレスなどを自動配布する仕組み                            | DNSと混同しやすいが、役割は「配布」                                  |
| NAT                    | プライベートIPとグローバルIPを変換する仕組み                  | 1対1変換のイメージで覚えると整理しやすい                             |
| NAPT                   | 複数端末をポート番号も使って1つのグローバルIPへ変換する仕組み | 家庭用ルータで一般的。NATより実用上よく使われる                      |
| ルータ                 | 異なるネットワーク同士を中継する機器                          | ネットワーク間の橋渡し役。経路制御を行う                             |
| スイッチ               | 同一LAN内でフレームを転送する機器                             | 宛先MACアドレスを見て転送する機器として覚える                        |
| デフォルトゲートウェイ | 他ネットワーク宛通信の出口となる装置やアドレス                | 同一ネットワーク外へ出るときの送り先                                 |
| HTTP                   | Webページ送受信に使う基本プロトコル                           | 暗号化はしない                                                       |
| HTTPS                  | 暗号化通信を行うHTTP                                          | HTTP over TLS/SSL と捉えると覚えやすい                               |
| SMTP                   | メール送信に使うプロトコル                                    | 送信担当。受信系と分けて覚える                                       |
| POP3                   | メールを受信して端末側に取り込む方式                          | 端末保存寄りのイメージ                                               |
| IMAP                   | サーバ上のメールを管理しながら受信する方式                    | 複数端末から同じメールを扱いやすい                                   |
| FTP                    | ファイル転送に使うプロトコル                                  | Web閲覧用ではなく、ファイル送受信用                                  |
| SNMP                   | ネットワーク機器の監視・管理に使うプロトコル                  | ルータやスイッチの状態監視で出やすい                                 |
| VLAN                   | 物理構成に依らず論理的にLANを分割する仕組み                   | 1台のスイッチ上でも部門ごとに分離しやすい                            |
| CSMA/CD                | 衝突を検出しながら共有媒体を利用する方式                      | 昔の共有型Ethernetの基本。スイッチ中心の現在は出番減だが試験では出る |

### データベース

| 用語             | 一言定義                                       | 注釈・備考                                         |
| ---------------- | ---------------------------------------------- | -------------------------------------------------- |
| 主キー           | 表の各行を一意に識別する属性                   | NULL不可・重複不可として扱うのが基本               |
| 外部キー         | 他表の主キーを参照する属性                     | 表同士の関連を表すために使う                       |
| 候補キー         | 主キーになり得る属性                           | 候補の中から1つを主キーに選ぶ                      |
| 正規化           | 重複や更新不整合を減らすために表を整理すること | 目的は見た目の整理ではなく、整合性向上             |
| 第1正規形        | 繰返し項目をなくし、属性値を単一化した形       | まず「1セル1値」にするイメージ                     |
| 第2正規形        | 部分関数従属をなくした形                       | 複合キーの一部だけに依存する属性を分離する         |
| 第3正規形        | 推移的関数従属をなくした形                     | キーでない属性が他のキーでない属性に依存しない形   |
| トランザクション | ひとまとまりとして扱う処理単位                 | 全部成功か全部失敗かで扱いたい処理の単位           |
| コミット         | 処理結果を確定すること                         | 確定後は通常元に戻せない                           |
| ロールバック     | 処理結果を取り消して元に戻すこと               | 異常時に整合性を保つために使う                     |
| 排他制御         | 同時実行による不整合を防ぐ制御                 | 複数利用者が同時更新するDBで重要                   |
| ロック           | 他処理からのアクセスを制限する仕組み           | 排他制御を実現する代表手段                         |
| デッドロック     | 複数処理が互いに待ち合って進まなくなる状態     | 「相手のロック解除待ち」が循環する状態             |
| ACID特性         | DBトランザクションが備えるべき4性質            | 原子性・一貫性・独立性・永続性                     |
| ビュー           | 実表をもとにした仮想的な表                     | 実データそのものを持たないものとして出ることが多い |
| インデックス     | 検索を高速化するための索引                     | 速くなる一方、更新時コストは増える                 |
| ER図             | 実体とその関連を表す図                         | 表設計前の概念整理にも使う                         |
| 多重度           | エンティティ間の対応数                         | 1対1、1対多、多対多 を表す                         |

### システム構成・信頼性

| 用語           | 一言定義                                          | 注釈・備考                                 |
| -------------- | ------------------------------------------------- | ------------------------------------------ |
| 可用性         | 必要なときに利用できる性質                        | 「使いたいときに使えるか」に注目する性質   |
| 信頼性         | 故障せず動き続ける性質                            | 壊れにくさ・故障しにくさ寄りの概念         |
| 保守性         | 修理や変更のしやすさ                              | 障害復旧や改修のしやすさに関係する         |
| 稼働率         | システムが利用可能である時間の割合                | MTBF / (MTBF + MTTR) が基本形              |
| MTBF           | 故障と故障の間の平均時間                          | 長いほど壊れにくい                         |
| MTTR           | 修理に要する平均時間                              | 短いほど復旧が早い                         |
| RAID0          | データを分散して高速化する構成                    | 冗長性はない。安全性目的ではない           |
| RAID1          | 同じデータを複製保存するミラーリング構成          | 耐障害性は高いが、容量効率は下がる         |
| RAID5          | パリティを分散配置して耐障害性を持たせた構成      | 1台故障に耐えられる構成として覚える        |
| RAID6          | 2重パリティで2台故障まで耐えられる構成            | RAID5より安全寄りだが容量効率は落ちる      |
| RAID10         | RAID1とRAID0を組み合わせた構成                    | 高速性と耐障害性を両立しやすい             |
| 冗長化         | 予備を持たせて障害に備えること                    | バックアップとは別物。止まらないための工夫 |
| 負荷分散       | 処理を複数装置へ分散して性能や可用性を高めること  | 性能向上と単一障害点の軽減に有効           |
| スケールアップ | 1台あたりの性能を上げる拡張                       | CPUやメモリ強化など、縦方向の拡張          |
| スケールアウト | 台数を増やして拡張すること                        | サーバ追加など、横方向の拡張               |
| クラスタリング | 複数台を連携させて1つのシステムのように動かす構成 | 可用性向上目的で出やすい                   |
| フェールセーフ | 故障時に安全側へ動作する設計                      | 壊れても危険を広げない考え方               |
| フールプルーフ | 誤操作しても危険になりにくい設計                  | 利用者のミスを前提にした設計               |
| フェールソフト | 一部故障しても機能を縮小して動作を続ける設計      | 全停止ではなく、機能を落として継続する     |

## 優先度B

### 開発・テスト・保守

| 用語                   | 一言定義                                       | 注釈・備考                                          |
| ---------------------- | ---------------------------------------------- | --------------------------------------------------- |
| ウォーターフォール     | 工程を順番に進める開発モデル                   | 要件定義→設計→実装→テストのように前工程へ戻りにくい |
| アジャイル             | 短い反復で柔軟に開発する手法                   | 変更に強い。スクラムなどと結び付けて出ることがある  |
| スパイラルモデル       | 反復しながら段階的に開発するモデル             | リスクを見ながら繰り返し開発する考え方              |
| プロトタイピング       | 試作品を作って要求確認する手法                 | 利用者イメージの具体化に有効                        |
| モジュール強度         | モジュール内部のまとまりの強さ                 | 強いほど望ましい。高凝集と近い感覚で覚える          |
| モジュール結合度       | モジュール間の依存の強さ                       | 弱いほど望ましい。強度と逆方向で覚える              |
| 単体テスト             | モジュール単位で行うテスト                     | プログラム部品ごとの確認                            |
| 結合テスト             | 複数モジュールを接続して行うテスト             | インタフェース不具合の検出に重要                    |
| システムテスト         | システム全体として行うテスト                   | 機能・性能・信頼性などを総合確認する                |

### 計算問題の概念

| 用語             | 一言定義                           | 注釈・備考                            |
| ---------------- | ---------------------------------- | ------------------------------------- |
| 稼働率           | システムが利用可能である時間の割合 | Aランクにも関連。式で解けるようにする |
| 応答時間         | 要求から応答完了までの時間         | 通信・処理・待ち時間の合計で考える    |
| 伝送速度         | 単位時間あたりに送れるデータ量     | bps が基本単位                        |

| 待ち行列         | 利用要求が並んで待つ状態のモデル   | 窓口問題のような形式で出る            |
| 利用率           | 装置や窓口が使われている割合       | 高すぎると待ち時間増加につながる      |
| 損益分岐点       | 利益が0になる売上高や販売量        | 経営計算の基本                        |
| 限界利益         | 売上高から変動費を引いた利益       | 損益分岐点計算に必要                  |
| ROI              | 投資額に対する利益の割合           | 投資効果評価で使う                    |
| 回収期間         | 投資額を回収するまでの期間         | 短いほど一般に望ましい                |
| 作業時間         | 作業に必要な時間                   | 工数計算の基本                        |
| 工数             | 作業量を人数×時間で表したもの      | 1人日、1人月などで表す                |
| クリティカルパス | 全体工期を決める最長経路           | Bランクとも重複するが計算問題で重要   |
| 情報量の式       | -log₂P で表される情報量            | 出るなら式適用型が多い                |
| 稼働率の式       | MTBF / (MTBF + MTTR)               | 数字を代入できるようにしておく        |
