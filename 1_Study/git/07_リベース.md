# リベース

リベースで履歴を整えた形で変更を統合する。

## コマンド

`git rebase <ブランチ名>`
ブランチの基点となるコミットを
別のコミットに移動する。

## マージとの違い

マージ
- コミットの履歴が残る
- コンフリクトの解決が比較的簡単
- マージコミットがたくさんあると履歴が複雑化する
リベース
- コミットの履歴が残らない
- 履歴をきれいに保つことができる
- コンフリクトを解決する場合、コミットそれぞれに解消が必要

プッシュしていないローカルの変更にはリベースを使う
プッシュした後はマージを使う
また、コンフリクトしそうならマージを使う。

## 基本の流れ

1. featureブランチを作成
2. masterとブランチで同時に作業し両方でコミット、枝分かれした状態に
3. featureブランチにmasterブランチの内容をリベースで取り込む。
4. featureブランチに居る状態で`git rebase master`
5. `git log`でリベースできたか確認
6. masterブランチに移動し、featureブランチをマージする。: `git merge feature`
7. `git push origin master`
8. featureブランチを削除:  `git branch -d feature`

## リベースでしてはいけないこと

GitHubにプッシュしたコミットを
リベースするのはNG
そもそも普通はpushできなくなるが、
`gif push -f`で出来てしまい、そうすると完全に履歴が壊れる

## pullの設定をrebaseに変更する

`git pull --rebase <リモート名> <ブランチ名>`
`git pull --rebase origin master`
マージコミットが残らないため、
GitHubの最新データを取得したいときだけのときは
--rebaseを使う。

### pullのデフォルトをリベースにする

`git config --global pull.rebase true`

### masterブランチでgit pullする時だけ

`git config branch.master.rebase true`

## リベースで履歴を書き換える

コミットを綺麗に整えてから
Pushしたい時に行う。
※GitHubにPushしていないコミット

### （復習）直前のコミットをやり直す方法

`git commit --amend`

### 複数のコミットをやり直す場合

`git rebase -i <コミットID>`
`git rebase -i HEAD~3`

↓コミットエディタが立ち上がり、直前3つのコミットが表示される
pick gh21f6d ヘッダー修正
pick 193054e ファイル追加
pick 84gha0d README修正

やり直したいコミットのeditに変更する
こうするとそのコミットがrebaseできるようになる
**edit** gh21f6d ヘッダー修正
pick 193054e ファイル追加
pick 84gha0d README修正

やりなおしたら実行する
`git commit --amend`

次のコミットへ進む（リベース完了）
`git rebase --continue`

### コミットの指定の方法

***HEAD~***
1番目の親を指定する。
HEADを基点にして数値分の親コミットまで指定する。

**HEAD^**
マージした場合の2番目の親を指定する。

### 手順まとめ

1. `git rebase -i` コマンドで対話的リベースモードに入る
2. 修正したいコミットをeditにしてコミットをエディタを終了する
3. editのコミットのところでコミットの適用が止まる
4. `git commit -amend`コマンドで修正
5. `git rebase --continue`で次のコミットへ行く
6. pickだとそのままのコミットの内容を適用して次へ行く

### コミットを並び替える、削除する

`git rebase -i HEAD~3`

pick gh21f6d ヘッダー修正
pick 193054e ファイル追加
pick 84gha0d README修正
↓
pick 193054e ファイル追加
pick gh21f6d ヘッダー修正
pick 84gha0d README修正

1. 84gha0dのコミットを消す
2. 193054eを先に適用する

### コミットをまとめる

squashで一つにまとめることができる

pick gh21f6d ヘッダー修正
pick 193054e ファイル追加
pick 84gha0d README修正
↓
pick gh21f6d ヘッダー修正
squash 193054e ファイル追加
squash 84gha0d README修正

### コミットを分割する

`git rebase -i HEAD~3`

pick gh21f6d ヘッダー修正
pick 193054e ファイル追加
pick 84gha0d READMEとindex修正
↓
pick gh21f6d ヘッダー修正
pick 193054e ファイル追加
edit 84gha0d READMEとindex修正

`git reset HEAD^` …84gha0dのこと、commitを取消しステージングもしていない状態になる
`git add README`
`git commit -m 'README修正'`
`git add index.html`
`git commit -m 'index.html修正'`
`git rebase --continue`
